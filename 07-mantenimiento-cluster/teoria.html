Módulo 07 · 4h

Mantenimiento del Cluster

Cordon/drain, backup y restore, upgrade del cluster y gestión de certificados. El lab es k3s. kubeadm y OpenShift quedan como referencia para un clúster de trabajo.

👤 Rol del administrador

El mantenimiento del cluster es responsabilidad exclusiva del admin. Un fallo en este proceso puede dejar el cluster sin servicio:

  • Actualizar el cluster sin interrumpir los workloads (rolling upgrade)
  • Hacer y restaurar backups del estado del cluster (SQLite, state.db)
  • Gestionar el ciclo de vida de los nodos: cordon, drain, uncordon
  • Administrar certificados TLS del cluster (caducan cada año)

📘 Teoría

Flujo de mantenimiento de un nodo

1. kubectl cordon     → SchedulingDisabled: no entran pods nuevos
2. kubectl drain      → Pods existentes migran a otros nodos
3. [mantenimiento: OS upgrade, parche, reinicio...]
4. kubectl uncordon   → El nodo vuelve a aceptar pods

En kubeadm los comandos son los mismos. En OpenShift: oc adm cordon, oc adm drain, oc adm uncordon.

Backup del estado del cluster

Este clúster tiene un solo server. k3s guarda el API en SQLite, a través de kine, en /var/lib/rancher/k3s/server/db/state.db. Ahí están los Pods, Deployments, Secrets, RBAC y el resto de objetos.

sudo systemctl stop k3s
sudo cp /var/lib/rancher/k3s/server/db/state.db /root/k3s-backup.db
sudo systemctl start k3s
Regla de oro: esa copia es el backup de todos los objetos del API. Sin ella, un fallo del server es irrecuperable. Quedan fuera las imágenes, los volúmenes del nodo y los certificados de /var/lib/rancher/k3s/server/tls/. Al restaurar, borra state.db-wal y state.db-shm antes de arrancar: si los dejas, SQLite reaplica el journal posterior al backup.

kubeadm. El estado vive en etcd. En un control plane:

sudo ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /opt/etcd-backup.db

sudo ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-restored
# hostPath del static pod /etc/kubernetes/manifests/etcd.yaml

OpenShift. Desde un master (oc debug --as-root node/<master>, luego chroot /host). El restore es el último recurso y el snapshot tiene que ser de la misma versión z-stream:

/usr/local/bin/cluster-backup.sh /home/core/assets/backup
sudo -E /usr/local/bin/cluster-restore.sh /home/core/assets/backup
oc adm wait-for-stable-cluster

Upgrade del cluster

k3s se actualiza volviendo a ejecutar el script de instalación, con INSTALL_K3S_VERSION. En este clúster la versión instalada es v1.37.2+k3s1.

1. Backup de state.db con k3s parado
2. Primero el SERVER (k3s-server, servicio k3s)
3. Luego cada WORKER, uno a uno
   cordon → drain → mismo script → uncordon
   (servicio k3s-agent)

El server tiene que quedar en la versión nueva antes que los workers. Un agent no puede ir por delante del server.

kubeadm. kubeadm upgrade apply en el primer control plane y kubeadm upgrade node en los demás. En cada worker: drain, instalar kubelet de esa versión, systemctl restart kubelet, uncordon.

OpenShift. oc adm upgrade channel y oc adm upgrade --to=4.x.y. El Machine Config Pool drena los nodos. En EKS, GKE o AKS el control plane lo sube el proveedor.

Gestión de certificados

Los certificados de cliente y de serving caducan a los 365 días. Las CA duran 10 años. Síntomas de un certificado caducado:

  • kubectl devuelve x509: certificate has expired
  • k3s no arranca

Se administran en k3s-server. Si al arrancar a un certificado le quedan menos de 90 días, k3s lo renueva solo.

# Ver cuándo caducan
sudo k3s certificate check --output table

# Forzar la renovación de todos y cargar los nuevos
sudo k3s certificate rotate
sudo systemctl restart k3s

kubeadm. kubeadm certs check-expiration y kubeadm certs renew all. Después hay que recrear los static pods moviendo un momento los YAML de /etc/kubernetes/manifests/.

OpenShift. Las hojas las rota la plataforma. oc get csr muestra las peticiones de los nodos. Forzar una hoja: oc adm ocp-certificates regenerate-leaf y luego oc adm wait-for-stable-cluster.
