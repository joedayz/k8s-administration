Este módulo cierra tres frentes distintos que todo admin de Kubernetes termina tocando tarde o temprano:

📘 Teoría

Gateway API vs. Ingress

Gateway API separa responsabilidades que Ingress mezclaba en un solo objeto:

GatewayClass (lo define el admin de plataforma)
      │
      ▼
   Gateway (una instancia concreta de balanceador)
      │
      ▼
   HTTPRoute (lo define cada equipo de app, sin tocar infraestructura compartida)

Cifrado de Secrets en reposo

Por defecto, los Secret se guardan en etcd en texto plano, codificados solo en base64 (que no es cifrado). EncryptionConfiguration le dice al API server que cifre ciertos recursos antes de escribirlos a etcd.

kubectl create secret ──▶ API server ──▶ [cifrado con la clave de EncryptionConfiguration] ──▶ etcd
Importante: habilitar el cifrado no recifra los Secrets ya existentes — hay que reescribirlos (reencrypt) explícitamente.

CNI y modos de kube-proxy

CNI: el plugin que le da IP a cada pod y conecta esa IP a la red del cluster (k3s usa Flannel/VXLAN por defecto). kube-proxy: programa las reglas que convierten un ClusterIP en conexiones reales a los pods detrás.

ModoCómo funcionaCuándo se usa
iptablesReglas de netfilter, recorridas secuencialmenteDefault histórico
ipvsTablas hash en el kernel, balanceo O(1)Clusters grandes
